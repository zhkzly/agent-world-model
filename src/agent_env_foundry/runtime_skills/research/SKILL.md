# Environment Research Method

Work from the complete supplied Need. Host anchors are addressing aids, not a
replacement semantic contract.

1. Before your first `search_sources` call, form a run-local Research Agenda.
   For every material part of the Need, list unresolved questions across:
   `world` actors/entities/relations; `success` workflows, preconditions and
   postconditions; `refusal` conditions and prohibited mutation; `dynamics`
   time/concurrency/persistence; `initial` meaningful starting relations;
   `authority` Need facts versus contingent external facts; `scope` coherent
   choices/assumptions/exclusions; and `substrate` mature relevant libraries or
   native formats without prescribing an implementation.
2. Every search query and focus must target one unresolved Agenda question.
   Search results and snippets are discovery aids only; never cite them.
3. Select candidate handles deliberately. Call `read_sources` with entries shaped
   `{source, focus}` — one narrow factual focus per selected source saying what
   exact passage would close the same unresolved Agenda question. The order you pass
   entries is the order the host attempts; it never searches for substitutes.
   Reread a retained `S#` source handle with a new focus instead of guessing.
4. Repeat search and reading adaptively when evidence exposes a semantic gap or
   contradiction. Treat typed no-match and truncation facts literally. Call and
   byte limits are ceilings, not a fixed recipe.
5. Cite only exact `E#` evidence handles returned with focused passages. Never
   write or reconstruct protected hashes. Disclose material conflicts rather
   than averaging them, and do not substitute evidence about one event or
   predicate for a different claim.
6. Give every requirement exactly one basis. Use `need` only for a requirement
   already mapped to an original Need clause and attach no evidence. Use
   `external_evidence` only with one or more resolvable `E#` handles.
7. Give every original Need clause exactly one disposition: `accepted` with
   mapped requirements, or `unsupported` with no requirement references. Never
   relabel an original Need clause as contract, assumption, or exclusion.
   Canonical package mechanics reach Builder separately and need no web proof;
   an explicit reset/isolation request remains Need-authorized. An
   under-specified Need often permits
   several coherent synthetic worlds: select one evidence-grounded variant and
   disclose its jurisdiction, workflow choices, assumptions, alternatives, and
   exclusions. Do not demand an exhaustive field/status taxonomy or unstated
   stakeholder preference. Mark a core-changing gap only when no disclosed
   coherent selection can satisfy an explicit Need clause, or when a contingent
   external fact remains unsupported after the available Research budget.
8. Describe capabilities, workflows, invariants, refusals, and meaningful
   initial-world conditions in observable language. Include a falsifiable
   consequence for each requirement.
9. Disclose assumptions, alternatives, and exclusions. Do not prescribe tools,
   storage tables, implementation modules, Tasks, verifiers, or rewards.

Stop only at semantic closure: every Need anchor is mapped or explicitly
proposed unsupported; every accepted external fact has exact cited evidence;
every core success has an observable precondition and postcondition; every core
refusal names its prohibited mutation; the initial world can exercise meaningful
success and refusal relations; contradictions are resolved or disclosed; and no
open gap can change core behavior. Resource ceilings cause failure, never a
weaker Draft.

Return only the requested structured Research Draft. Verify every external
citation is an exact returned `E#`, every Need-basis requirement has zero
evidence, and no snippet or model recollection is evidence. If a fresh Evidence
Reviewer returns typed blocking findings, use them in the same producer history
before returning a complete revised Draft. Residual limitations alone are
non-blocking.
