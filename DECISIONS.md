# Accepted Decisions

## 2026-08-30 — Delete duplicated qualification and robustness gates

- Product checks must map to one explicit S1, S2, or paper-experiment claim.
- S1 proves executable environment capabilities; S2 proves concrete Tasks;
  paper evaluation owns robustness breadth and corpus targets.
- S1 runs one representative positive public execution per capability.
- The independent Native Auditor checks only required native effects and
  collateral. It does not duplicate public process, final answers, or reports.
- Host validates every AnswerField against a real public source occurrence.
- Each capability declares only its own necessary final-answer fields.
  Condition branches may use different schemas.
- `reportable_field_ids` and automatic singleton answer profiles are deleted.
- Atom admission keeps two fresh witnesses plus no-op, applicable wrong target,
  and constructible wrong answer.
- ForEach admission keeps two fresh witnesses, no-op, and one representative
  omitted member.
- If admission keeps two fresh witnesses for the condition-selected branch.
- Mandatory alternative route, reverse order, every-member partials,
  per-occurrence AgentChoice perturbation, manufactured collateral, and
  result-object mutation are removed from production admission.
- Corpus count/structure floors and optional robustness tests are paper
  experiment metrics, not product release gates.
- Historical C3/F mutation and challenge records are recoverable from Git but
  no longer define current implementation authority.

## S1/S2 clean-break architecture

- Only EnvironmentRelease v2 is supported; no v1 compatibility or fallback.
- S1 publishes public actor and protected TaskSemantics surfaces.
- Environment Builder, TaskSemantics Author, and Native Auditor Author use
  isolated workspaces/lineages.
- Expected Semantics sees the accepted Need and frozen public surface, not
  actor source or native state.
- Framework owns schemas, manifests, identities, execution, receipts,
  publication, Task compilation, admission, and verdicts.
- Generated code and model prose never self-authorize.
- S2 is Goal-first. Graph/random walk/program synthesis may search but cannot
  create Task meaning.
- GoalProgram contains only Atom, All, If, and ForEach.
- TaskChecker freezes before the final instruction is exposed.
- Public witness and later S3 actor receive exactly that instruction.
- Public acting uses a Host-owned Responses tool loop; Codex SDK is reserved
  for the three release-local code artifacts.
- Protected state may select/verify a Task but never supply acting-time
  operands. Starts are reset-only.
- TaskPack identity is separate from TaskAssessment and CorpusManifest.
- TaskAssessment uses fresh public trials after admission and records failures;
  CorpusManifest binds exact TaskPack/assessment pairs, while corpus thresholds
  and counts remain experiment policy rather than Task admission.
- Task definitions bind logical referents; every run resolves fresh protected
  bindings after reset.
- Parameter swaps and paraphrases do not count as new Task structures.
- Universal State IR, unrestricted per-Task verifier code, hidden setup,
  provisional releases, mutable aliases, demo/MVP paths, and domain-specific
  Framework branches are forbidden.

## Stage boundaries

- S1: qualified immutable EnvironmentRelease.
- S2: TaskPack, TaskAssessment, CorpusManifest.
- S3: acting-Agent Episodes and reward/abstention mapping.
- S4: SFT/RL over verified Episodes.
- Research remains evidence-grounded and separate from Builder code authoring.
- MCP/HTTP/provider envelopes are adapters, not environment semantics.
