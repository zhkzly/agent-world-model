# Choose Runtime Remediation From Evidence

## Keep the candidate explanations alive

An invalid object, missing field, weak proposal, malformed JSON, refusal,
timeout, or failed test can be caused by:

- ambiguous or missing Direct Prompt/input;
- missing reusable Agent Runtime Skill method or self-check, or an incorrect
  Skill on a Direct route;
- missing/misleading runtime context;
- unsuitable model/profile/route/response mode/budget;
- parser, schema, validator, current graph coordinator, adapter, or upstream input;
- correction feedback that lacks an actionable bounded story.

Do not call one surface defective because of one model result. Select a small
real experiment that can weaken the alternatives.

## Route information to the owner

- Project-execution Agent: safe investigation narrative and local source paths.
- Control plane: authority, budget, settlement, attempt, retry, and
  continuation facts only.
- Runtime role Agent: only an authorized bounded correction story stating what
  failed, what is frozen, what may change, and what complete replacement is
  required.
- Human: authority, ambiguity, credentials, risk, or release-policy decisions.

Never pass raw opaque Provider text or an adapter error to a runtime role Agent
as semantic feedback.

## Select the mechanism

- Improve a proven Direct Prompt/input, Agent-only Skill method, or
  model/profile cause, audit live homologues, then make fresh generation.
- Use bounded correction only for a coherent candidate, precise actionable
  feedback, preserved valid work, and explicit authority.
- For formatting, choose from Prompt/Skill self-check, correction, response
  mode/profile, adapter extraction, or feedback improvement based on evidence;
  do not hard-code an error label to one remedy.
- Put IDs, wrappers, ordering, serialization, authority, and known
  parser/validator defects in deterministic code. Keep business semantics with
  the model where that is the product work.
- Retry only after an explicitly closed transient transport fact and through
  definition-authorized policy.

Fresh generation follows a causal change. A correction turn is not a disguised
retry: it requires intact candidate state, bounded requested change, useful
feedback, and authority.
