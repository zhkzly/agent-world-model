# Attribution and Feedback

## Five-lens evidence

For every lens, record an exact coordinate plus a path/profile/projection:

1. **Project Agent view** — Can the Code Agent choose the next read from the
   compact scene/index/path map? If evidence exists but requires broad search,
   the view is weakened.
2. **Effective Prompt/input** — Does the exact rendered Prompt and frozen input
   projection disclose the facts and scope needed by this node?
3. **Runtime Skill / Direct no-Skill** — For Codex Agent, does the one mounted
   bundle supply the reusable method, self-check, and correction habit? For
   Direct, are Skill/Hook/tool/profile instruction surfaces absent?
4. **Code/execution** — Name the live sub-lane: CLI/execution safety,
   verifier/gate, replay/resume/state, Runtime/Judge isolation, legacy path,
   parser/compiler/validator/current graph coordinator, or provider/transport.
   A cleanroom path that reaches legacy authority is a cutover failure before
   it is any other execution diagnosis.
5. **Feedback/observability** — Can the intended recipient act without reading
   private Provider text or broadly searching source?

Do not write “Prompt audited” or “Skill audited” without the exact effective
surface and an observation that could falsify the conclusion.

## Safe story shape

Every Feedback story contains:

1. coordinate and phase;
2. what happened;
3. what is known;
4. what remains unknown;
5. next permitted read or action.

Route that story to the recipient who can use it:

- **Project Agent:** compact scene, known/unknown facts, and local paths to the
  effective Prompt/input, mounted Skill, profile, implementation, and evidence.
- **Control plane:** authority, budget, attempt, ownership, settlement, retry,
  and continuation facts. It never invents semantic corrections.
- **Runtime Agent:** only an authorized bounded correction: rejected condition,
  frozen facts, permitted mutation, and required complete replacement.
- **Human:** only authority, ambiguity, credentials, risk, or release policy
  decisions.

Never send raw Provider content, credentials, endpoint, private session state,
or opaque infrastructure diagnostics to a runtime model as semantic feedback.

## Feedback is not one mechanism

Choose among:

- improve the normal scene or on-demand project Agent view;
- add a safe typed diagnostic at the real failing boundary;
- pass a precise authorized correction brief to the same Agent session;
- regenerate after a causal Prompt/Skill/profile change;
- stop with `needs_human` when no automated recipient owns the decision.

When validation identifies a Candidate file, verify that changing that file can
satisfy every frozen condition. If two frozen rules conflict, routing repair to
one generated file is misleading Feedback; report the contradiction to the
owning upstream Artifact instead.

## Test output is Agent Feedback

A failing boundary test must name:

- node/boundary and owner lens;
- frozen-input or committed-closure provenance;
- one poisoned condition;
- expected versus actual stable code/path/category/terminal;
- elapsed time and last completed phase.

A bare assertion, opaque exception, or unexplained stall is a harness
observability defect. Improve that output and prove it locally before steering
a Prompt, Skill, contract, or model retry from it.
